# SPECTRA | Synchrotron XAS Reference Spectra Dashboard

**Interactive reference library for X-ray absorption spectroscopy (XAS)**, with XANES and EXAFS visualizations, reference-level metadata, and downloadable spectra for reuse in Athena and Larch.

**Live dashboard:** https://xeniadegraciam.github.io/SPECTRA/  
**Synchrotron sample preparation and measurement procedures:** https://xeniadegraciam.github.io/sop_chorover_lab/Synchrotron.html

> **Scope and provenance:** SPECTRA presents reference spectra and processing products. The unnormalized absorption spectra exported from Athena projects are **not necessarily original beamline acquisition files**. Facility and beamline labels must be verified against source records before being treated as confirmed provenance.

## 1. What is in the dashboard?

The web dashboard supports:

- **Element-based navigation:** choose a supported element using the interactive periodic-table interface.
- **Facility/beamline navigation:** explore references by the facility and beamline labels recorded in the database. Some labels are provisional or unverified.
- **Four XAS/EXAFS views:** a near-edge zoom, normalized XANES, k²-weighted EXAFS χ(k), and Fourier-transform magnitude versus radial distance.
- **Reference selection:** emphasize a selected spectrum and display its associated metadata.
- **Downloads:** obtain files associated with the selected reference, when the corresponding files are present in the published repository.

**Notes:**

- The directories shown for Pb are prospective, not evidence of published Pb data.
- The local `C:\Users\...` or `D:\...` paths are Windows filesystem paths, **not public URLs**. The website uses repository-relative paths.

## 3. Data products and scientific meaning

| Product | Example path or filename | Description | Caveat |
| --- | --- | --- | --- |
| Athena project | `Fe/athena_projects/Fe_NSLSII_references.prj` | Original Athena project containing reference groups and analysis context | A project download can include more than the selected reference |
| Unnormalized μ(E) | `Fe/unnormalized/Goethite_Nat_001_mu.dat` | Two-column ASCII spectrum: energy (eV), absorption μ(E), taken from the Athena group's stored x/y arrays | **Not equivalent** to original detector channels or acquisition files |
| XANES JSON | `Fe/processed/Goethite_Nat_001_xanes.json` | Processed near-edge arrays used for plotting | Normalization and energy calibration depend on upstream processing |
| EXAFS JSON | `Fe/processed/Goethite_Nat_001_chi_k.json` | Processed χ(k) data | Confirm k-weighting and background-subtraction settings before quantitative comparison |
| FT-EXAFS JSON | `Fe/processed/Goethite_Nat_001_ft_exafs.json` | Fourier-transform data for plotting | FT **magnitude alone** does not retain the complex FT phase |
| Metadata JSON | `Fe/metadata/Goethite_Nat_001_metadata.json` | Reference-specific metadata, when present | Completeness varies by reference |
| Metadata overrides | `dashboard_metadata_overrides.json` | Curated processing parameters and metadata merged into the dashboard | Should be checked against the Athena project and laboratory records |
| Index | `database_index.json` | Maps sample IDs to relative data-file paths and provenance fields | All linked paths must exist in the deployed repository |
| Export audit | `athena_export_audit.json` | Reconciliation and export status for Athena groups | Review after every rebuild |

### Downloads in the interface

Depending on file availability, the selected-reference section offers:

1. **Original acquisition file:** shown only when a verified acquisition file is registered and published.
2. **Athena project (`.prj`):** the project containing the selected reference.
3. **Unnormalized μ(E) (`.dat`):** energy and absorption values stored in Athena, suitable for independent normalization or reprocessing.
4. **Normalized XANES (`.dat`):** a text export of available processed XANES arrays.
5. **EXAFS χ(k) (`.dat`):** a text export of available processed EXAFS arrays.
6. **FT-EXAFS (`.dat`):** a text export of available Fourier-transform arrays; interpret magnitude-only exports accordingly.
7. **Complete reference ZIP:** only when a ZIP path has been registered and the package exists.

Buttons are conditional. A missing button generally means that the corresponding downloadable product has **not been registered or cannot be generated from the available arrays**. It does not mean that the scientific measurement was never made.

## 4. Running SPECTRA locally

### Requirements

- Python 3 with a working `python` command.
- A modern browser and an internet connection for the Plotly JavaScript library loaded from its CDN.
- The repository files in the layout shown above.

Open a terminal in the `SPECTRA` directory. For the current Windows/OneDrive location:

```powershell
cd "C:\Users\xeniadegracia\OneDrive - University of Arizona\Research\FieldNotes\Synchrotron\Rob_Standards\Dashboard\SPECTRA"
python -m http.server 8000
```

Open **http://localhost:8000/**.

Check these URLs if a reference does not load:

- http://localhost:8000/dashboard_export/database_index.json
- http://localhost:8000/dashboard_export/Fe/processed/Goethite_Nat_001_xanes.json

**Do not open `index.html` using a `file://` URL.** Browsers commonly restrict JavaScript `fetch()` requests to local files; the local HTTP server avoids that problem.

The dashboard's data root is relative to `SPECTRA/index.html`:

```javascript
const DATA_ROOT = "dashboard_export/";
```

Do not change this to `SPECTRA/dashboard_export/` unless `index.html` is moved outside the `SPECTRA` directory.

## 5. Rebuilding Athena downloads

The included `build_athena_downloads.py` script extracts the **stored energy and absorption arrays** from the three `.prj` files, creates ASCII `.dat` exports, copies the Athena projects into the published data tree, updates the index, and writes an audit report.

### Prerequisites

Install NumPy in the Python environment used for the exporter:

```powershell
python -m pip install numpy
```

Ensure that the following files exist directly inside `SPECTRA/`:

```text
build_athena_downloads.py
As_refs_USB.prj
Fe_NSLSII_references.prj
S_refs_athena.prj
dashboard_export/database_index.json
```

Run:

```powershell
python build_athena_downloads.py
```

Then inspect:

```text
dashboard_export/athena_export_audit.json
```

The current delivered export audit records **40 successful exports**: As 10, Fe 26, and S 4. Recheck these counts after any change to the project files or database index.

### What the exporter does *not* do

- It does **not** recover original I0, It/I1, fluorescence detector channels, or the beamline's original acquisition files unless those data are separately available.
- It does **not** regenerate the existing normalized XANES, χ(k), or FT-EXAFS JSON files.
- It does **not** establish beamline provenance merely because a project filename contains a facility name.
- It does **not** automatically discover new projects. The `projects` mapping in the script must be extended, and matching reference records must be present in `database_index.json`.

The exporter stops or reports a problem when a reference cannot be matched uniquely or its arrays fail validation. Check the audit rather than assuming every reference was exported.

## 6. Database index and provenance

`dashboard_export/database_index.json` is a JSON **array** of reference records. Example:

```json
{
  "sample_id": "Goethite_Nat_001",
  "athena_group": "Goethite_Nat_001",
  "element": "Fe",
  "edge": "K-edge",
  "xanes_file": "Fe/processed/Goethite_Nat_001_xanes.json",
  "chi_file": "Fe/processed/Goethite_Nat_001_chi_k.json",
  "ft_file": "Fe/processed/Goethite_Nat_001_ft_exafs.json",
  "metadata_file": "Fe/metadata/Goethite_Nat_001_metadata.json",
  "unnormalized_download": "Fe/unnormalized/Goethite_Nat_001_mu.dat",
  "athena_project_download": "Fe/athena_projects/Fe_NSLSII_references.prj"
}
```

The example shows the core file-link fields; actual entries may include additional metadata and provenance fields.

### Facility and beamline quality control

Some current facility labels are **inferred from project names or source paths**, not independently confirmed for every reference. Beamline assignments remain unverified where acquisition records have not been checked. Treat the navigation labels as organizational metadata until provenance has been validated.

A stored `project_file` or `original_source_path_from_athena` may refer to a private Windows location. It is useful for internal traceability but **does not create a downloadable link**. Before public deployment, review these fields for personal information, institutional restrictions, or paths that should not be disclosed.

## 7. Publishing with GitHub Pages

The site is served from the repository root at:

For a repository-root GitHub Pages deployment, commit `index.html`, `dashboard_export/`, and the assets needed by the dashboard. The GitHub Pages publishing source must include those files in the correct relative structure.

**Before pushing:**

1. Confirm that `database_index.json` contains valid relative paths.
2. Confirm that every referenced `processed/`, `metadata/`, `unnormalized/`, and `athena_projects/` file intended for download is present in the repository.
3. Confirm that the local dashboard loads all four plots for representative As, Fe, and S references.
4. Test each download type. Remember that some downloads are intentionally hidden when the underlying data are absent.
5. Review Athena projects and JSON metadata for private paths, unpublished data, and redistribution permissions.
6. Push changes, allow GitHub Pages to deploy, and hard-refresh the public site if the browser displays an older version.

GitHub Pages serves **static files**. It does not run the Python exporter. Rebuild and commit the exported data whenever Athena projects change.

## 8. Quality assurance and scientific limitations

- **Raw versus processed:** an Athena-stored unnormalized μ(E) array is not automatically the original acquisition file.
- **Reference identity:** sample IDs and Athena group labels should be reconciled; normalized filename matching alone is not a substitute for scientific verification.
- **Energy alignment:** verify calibration and any energy shifts before comparing edge positions or performing linear-combination fitting.
- **Normalization:** pre-edge and post-edge ranges can affect normalized spectra; consult the reference metadata and processing history.
- **EXAFS:** χ(k), k-weighting, k-range, window function, and Fourier-transform conventions affect the appearance and interpretation of the plots.
- **Fourier transforms:** FT magnitude is not the complete complex Fourier transform and does not preserve phase by itself.
- **Missing data:** an absent plot or download should be investigated using the browser developer console, database index, and file paths.
- **Provenance:** do not infer SSRL/NSLS-II beamline assignments solely from filenames.

## 9. Troubleshooting

| Problem | What to check |
| --- | --- |
| Blank dashboard or missing plots | Serve via `python -m http.server`, not `file://`; inspect browser console |
| `database_index.json` returns 404 | `index.html` must be next to `dashboard_export/` |
| One reference fails to plot | Check its `xanes_file`, `chi_file`, `ft_file`, and metadata paths in the index |
| Download button is absent | Verify that the corresponding file exists or that the processed JSON contains the required arrays |
| Athena project downloads but contains several references | This is expected: `.prj` files are project-level containers |
| `build_athena_downloads.py` fails | Verify `.prj` filenames, NumPy installation, and existing index entries; inspect the audit |
| GitHub Pages shows an old version | Confirm the push and deployment, then hard-refresh or clear cache |
| Local site works but published site fails | Check case-sensitive filenames, committed files, and repository-relative paths |

## Sulfur K-edge: XANES-only processing

Sulfur K-edge reference spectra in SPECTRA are analyzed and displayed using **XANES only**. Sulfur K-edge XANES is highly sensitive to sulfur oxidation state and bonding environment, allowing comparison of reduced sulfur species, intermediate oxidation states, and sulfate. The low sulfur K-edge energy (approximately 2.47 keV) makes experiments more sensitive to air absorption, sample thickness, and instrumental constraints. Furthermore, sulfur K-edge spectra commonly feature strong near-edge resonances, and a sufficiently long, high-quality post-edge range for reliable EXAFS analysis is not necessarily available in this dataset. **EXAFS is not physically impossible at the sulfur K-edge**, but no sulfur EXAFS analysis is claimed for this repository.

When sulfur is selected, the dashboard shows only pre-edge/near-edge and normalized XANES panels. It does not load, plot, calculate, or offer downloads for sulfur EXAFS χ(k) or FT-EXAFS. Unnormalized μ(E), normalized XANES, and the original Athena project remain downloadable where published. The database index omits sulfur EXAFS file references. For As and Fe, existing EXAFS functionality remains unchanged.
